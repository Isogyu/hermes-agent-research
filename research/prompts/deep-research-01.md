# 調査依頼: Hermes Agent（Nous Research）について、公開情報で分かることと分からないことの切り分け

## 目的

私は Nous Research の Hermes Agent を、手元の PC で実際に動かして検証しています。私は普段 Claude Code と Codex CLI を使っています。知りたいのは次の 2 点です。

- **問い 1**: Hermes が Claude Code や Codex を超える可能性のある分野や作業はあるか。あるなら、それはどこか。
- **問い 2**: Hermes は仕事のあり方を変えられるか。つまり、人が都度指示して結果を受け取る使い方ではなく、常駐して業務を引き受け、使うほど任せられる範囲が広がる、という働き方が実際に成り立つか。

これまでの検証は、機能を順に試すだけになりかけています。そこで、実験を再開する前に、公開情報で既に分かることを調べ尽くしたいです。この調査の成果は次の 2 つです。

1. 公開情報で既に答えが出ていること（私が実験し直す必要がないこと）
2. 公開情報では答えが出ておらず、かつ答えが分かれば問い 1・問い 2 の答えが変わること（私が実験すべきこと）

特に 2 が欲しいです。機能の紹介や README の要約は要りません。調査項目 A〜E のうち、E（他の道具との比較）と B（実運用の報告）を最も重視してください。

## 対象の区別

次の 3 つを混同しないでください。どの主張がどれについてのものかを必ず明記してください。

- **Hermes Agent**: OSS のエージェント本体（GitHub: NousResearch/hermes-agent）。私が検証したのは 2026 年 11 月時点の v0.23.3 系です。
- **Hermes Foundry**: Hermes Agent を Microsoft Foundry の hosted agent として動かすためのパッケージ（NousResearch/hermes-foundry）。
- **Hermes Enterprise**: 商用の提供形態。公開コードには実体が見当たりません。

Nous Research の言語モデル「Hermes」シリーズ（Hermes 3、Hermes 4 など）は別物なので、対象外です。

## 私が既に実測したこと

以下は調べ直さなくて構いません。ただし、同じことを既に公開している人がいるか、反対の結果を報告している人がいるかは知りたいです。

- 明示的に保存させた Skill は効く。文書にない慣習が必要な業務で、Skill なしは 0/3、明示保存の Skill ありは 3/3 で合格した。
- 自動の振り返り（バックグラウンドレビュー）が書く Skill は、汎用の手順書になり、具体的な値を落とす。同じ業務で 0/3。同一会話で 3 回繰り返しても、振り返りのプロンプトを変えても改善しなかった。
- 自動の振り返りは、1 回実行（`-z`、`chat -q`）、cron、子エージェントでは起動しない。
- スクリプトつきの Skill は手数とトークンを約 3 分の 1 にするが、業務ルールが変わると 0/3 で誤り、成功と報告する。
- 最小のリクエストが約 1 万トークンあり、Skill の一覧は個数に比例して増える（2000 個で約 5.8 万トークン）。
- エージェントが通常のターンで書く Skill は、既定設定では安全検査を通らない。
- 「Collective Wisdom」は公開の 2 リポジトリに実装がない。
- Claude Code や Codex への委任は動くが、遅くて脆い。

## 調べてほしいこと

### A. 学習と自己改善の主張の裏づけ

- Nous Research が Hermes Agent の学習、Skill、自己改善について公式に主張していることと、その根拠（ベンチマーク、方法、データ）。「20 個以上の自作 Skill で 40% 速い」という数字の出どころと測定方法。
- 第三者による独立した測定や再現の有無。条件、回数、結果。
- 別リポジトリ NousResearch/hermes-agent-self-evolution（DSPy / GEPA による Skill の最適化）の仕組み、成熟度、実際の利用報告、効果の報告。
- 自動で生成された Skill の質についての GitHub Issue、Discussion、Discord の公開ログ、利用者のブログでの報告。
- 学術研究で、エージェントが自分で書く Skill ライブラリや手順メモリの効果と失敗の仕方について分かっていること（Voyager 以降の系譜、Agent Skills の評価、手順の陳腐化や誤った一般化の研究）。Hermes に当てはまる知見だけで構いません。

### B. 実運用の報告

- Hermes Agent を数週間以上、実際の業務で使った人や組織の報告。何に使い、何が続き、何をやめたか。
- 長期運用での具体的な問題: 費用の伸び、メモリや Skill の肥大と劣化、コンテキスト圧縮後の品質、無人実行（cron、ゲートウェイ）の失敗の仕方、更新による破壊的変更。
- GitHub の Issue で、未解決のまま多く支持されているもの、繰り返し報告されているもの。
- 利用をやめた人、別の道具に移った人の理由。

### C. 企業利用（Enterprise と Foundry）

- Hermes Enterprise の実体: 提供内容、価格、契約形態、提供開始の時期、OSS 版との差、導入事例。公式発表と報道を区別してください。
- 「Collective Wisdom」の公式の説明: 何を共有し、どこで動き、いつ提供されるのか。実装の所在。
- Hermes Foundry と Microsoft の関係: 公式な提携なのか、提供の段階（POC、preview、GA）、必要なライセンスと費用、導入報告。
- 企業が導入するときの障害として指摘されていること（権限、監査、データの所在、マルチテナント、サポート）。

### D. セキュリティ

- 公開されている脆弱性、アドバイザリ、監査結果、研究者による解析。修正の状況。
- Skill やメモリを経由した永続的なプロンプトインジェクションについて、実証された攻撃と公式の対応。
- 承認機構と実行の隔離について、公式が保証している範囲と、していない範囲。

### E. 他の道具との比較

- Claude Code、Codex CLI との比較で、根拠のある差として挙げられていること。宣伝文句ではなく、測定や具体的な事例に基づくものだけ。OpenClaw、Letta など、常駐型や記憶を持つ他のエージェントとの比較も補助的に見てください。
- 構造上の違いの整理。Hermes にあって Claude Code や Codex にないもの、その逆。候補は、常駐とメッセージ基盤（Teams、Slack、Telegram など）からの依頼、定期実行、会話をまたぐ記憶と利用者モデル、Skill の自動蓄積、モデルを選ばないこと（安いモデルやローカルモデルでの運用）、複数エージェントの並列作業です。Claude Code や Codex の側も 2026 年に Skill、メモリ、定期実行、クラウド実行、チャットからの呼び出しを備えてきているので、差が現時点でも残っているかを、双方の現行版で確認してください。
- 「Hermes でなければできないこと」「Hermes のほうがうまくいく作業」として、実際の利用者が具体例つきで挙げているもの。コーディング以外の業務（調査、定型の事務、監視、連絡の一次対応、個人秘書的な用途）を特に知りたいです。
- 逆に、Claude Code や Codex で十分、またはそちらが優れているとされている用途。
- Claude Code や Codex と併用している人の役割分担。
- 「仕事のあり方が変わった」という報告の中身。何を任せ、人の作業時間や役割がどう変わり、どこで人の確認が残ったか。数週間以上続いた事例と、続かなかった事例の両方。

## 出力の形式

### 1. 主張の一覧表

列は次のとおりにしてください。

| 主張 | 対象（Agent / Foundry / Enterprise） | 根拠の種類 | 出典 URL | 日付と版 | 信頼度 |

根拠の種類は次のいずれかです。「公式の主張（根拠なし）」「公式の主張（方法つき）」「第三者の測定」「第三者の体験談」「ソースコードや Issue の一次情報」「報道」「推測」。

### 2. 私の実測との照合

「私が既に実測したこと」の各項目について、公開情報で既に知られているか、反対の報告があるか、見当たらないかを書いてください。見当たらない場合は、どんな語で探して見つからなかったかも書いてください。

### 3. 空白の一覧

公開情報で答えが出ていない問いを列挙してください。各項目に次を添えてください。

- なぜ答えが出ていないと判断したか
- 答えが分かると、問い 1 と問い 2 のどちらの答えが、どう変わるか
- 1 台の PC と無料から低額の API で検証できそうか

### 4. Hermes が優位になりうる領域の候補

問い 1 に対して、Hermes が Claude Code や Codex を超える可能性のある分野や作業を、根拠の強さの順に並べてください。各候補に、そう考える根拠、Claude Code や Codex の現行機能で同じことをする場合の方法、残る差を書いてください。候補が見つからなければ、そう書いてください。

### 5. 検証する価値が高い仮説の候補

空白の一覧と 4 の候補から、問い 1・問い 2 への影響が大きく、手元で検証できるものを 5 個前後選んでください。各仮説は「ある作業で、Hermes は Claude Code や Codex よりこの指標で優れる（または劣る）」のように、同じ作業を両方にさせて比べられる形にしてください。各仮説に、反証する方法と、どんな結果が出たら仮説を捨てるかを書いてください。

## 守ってほしいこと

- 英語の情報源を主に調べ、日本語の情報源も補助的に見てください。
- 一次情報（GitHub のリポジトリ、Issue、PR、リリースノート、公式ドキュメント、公式ブログ、論文）を優先してください。二次記事は、一次情報をたどれた場合にだけ事実として扱ってください。
- Hermes Agent は更新が速いので、情報の日付と対象の版を必ず書いてください。2026 年前半以前の情報は、現行版に当てはまるかを確認してください。
- AI が量産したと見られる紹介記事や、公式の文言を言い換えただけの記事は、根拠に数えないでください。
- 確認できた事実と、あなたの推測を分けてください。分からないことは分からないと書いてください。
- 見つからなかったことも成果です。探して見つからなかった場合は、その旨を書いてください。
