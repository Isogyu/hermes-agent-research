# E003 固定費と Skill 一覧の伸び方（2026-11-20）

- **目的**: Hermes が1リクエストごとにモデルへ送る量と、Skill が増えたときの伸び方を実測する。
- **背景・仮説**: 「Skill が蓄積するほど賢く安くなる」という主張に対し、Skill の一覧自体が毎回のコストになるなら、蓄積には上限があるはず。反証条件: 一覧に上限・検索・要約があり、Skill 数に対して頭打ちになる。
- **方法**: 台本どおりに応答する偽 LLM（`lab/mock/mock_llm.py`）へ `hermes -z` を向け、受け取ったリクエストを全部記録（`lab/mock/run.sh`）。トークンは「JSON 文字数 / 4」の見積もり。合成 Skill は `lab/mock/gen_skills.py` で作成。
- **結果**（`lab/runs/b0-baseline`, `b1-skills-*`）:

| 条件 | system 文字数 | うち Skill 一覧 | 見積もりトークン（1リクエスト） |
|---|---|---|---|
| 初期状態（同梱 Skill 44個） | 11,567 | 3,354 | 10,452 |
| +100個 | 20,959 | 12,767 | 12,825 |
| +500個 | 58,559 | 50,367 | 22,325 |
| +2000個 | 199,562 | 191,367 | 57,951 |

  - ツール定義は 18個で 30,037 文字。固定費の約7割はツール定義。
  - 見積もり 10,452 に対し、E002 で Ollama の実トークナイザは同じ依頼を 10,019 と数えた。見積もりは約4%高い程度。
  - 一覧は Skill 1個あたり約94文字（約24トークン）で線形に伸びる。2000個でも全件が載り、上限も検索もない。
  - 説明は60字で切られる。合成 Skill はどれも `Build the monthly sales report for region 0000 from the...` となり、地域番号以降の差が消えた。
  - 12回のツール呼び出しを行う実行（`r1-review-oneshot`）は API 呼び出し13回、入力合計 141,858 トークン。毎回ほぼ全量を送り直す。
  - 初回起動は55秒（同梱 Skill の展開を含む）、2回目以降は5〜11秒。モデルの応答時間はほぼ0なので、これは Hermes 自体の起動時間。
- **解釈**:
  - 個人が数十個の Skill を持つ範囲では一覧の負担は小さい。組織で数百〜数千個を1つの HERMES_HOME に集めると、一覧だけで固定費が倍以上になる。
  - 60字の切り詰めは、似た業務の Skill が多い組織ほど選択を難しくする。
  - Skill を1つ使うには `skill_view` の往復が1回増える（全プロンプトをもう1回送る）。プロンプトキャッシュがない接続先では、Skill が探索の手数を1回以上減らさない限り、使うほうが高くつく。
- **限界・反証**: プロンプトキャッシュが効く接続先（Anthropic など）では送り直しの単価が大きく下がるので、金額の結論は変わりうる。モデルが多数の一覧から正しく選べるかは、偽 LLM では測れない。`skills.external_dirs` やカテゴリ単位の絞り込み設定は未調査。
- **次の行動**: 実モデルで「一覧が大きいときの選択精度」を測る（要 API 承認）。カテゴリ無効化など、一覧を絞る設定の有無を調べる。
