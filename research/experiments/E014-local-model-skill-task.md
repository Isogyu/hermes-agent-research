# E014 ローカル 4B モデルで Skill つき業務（2026-11-21）

- **目的**: ツールセットを絞れば、ローカルモデルで Skill 再利用実験ができるかを確かめる。
- **方法**: 偽 LLM で `-t` ごとの固定費を測定。その後 `hermes-lab-qwen3-12k`（qwen3 4B、実コンテキスト 12k）に E012 の月次レポート業務（2月、スクリプトつき Skill あり）を `-t terminal,skills -z` で実行。
- **結果**:
  - 固定費（見積もり）: 既定 10,452 → `terminal,file,skills` 6,404 → `terminal,skills` 5,117 → `skills` 3,868 トークン。
  - l3（1回目）: Skill を読み、スクリプトの絶対パスを引用符なしで実行。`Nous Research` の空白で失敗。198秒で `Gateway disconnected`（原因未特定、当時の負荷平均は15）。**空白はこちらの環境の問題。**
  - l4（HERMES_HOME を空白のないパスに置いて再実行）: 185秒、7回の呼び出し、入力 43,999（うちキャッシュ 40,121）。コンテキストはあふれなかった。モデルは `skill_view` が返した絶対パスを使わず、相対パス `productivity/monthly-sales-report/scripts/…` で実行して失敗。作業フォルダ内を探して見つからず、「スクリプトが見つからない」と報告して終了。得点 0/6。捏造はしなかった。
- **解釈**:
  - 仕組みの上では、ツールを絞れば 8GB の機械でも Hermes は回る。1呼び出し約26秒（プロンプトのキャッシュが効く）。
  - 4B のモデルは、上位モデルが書いた Skill（`<skill-directory>/scripts/…` という書き方）を正しく使えなかった。Skill は書いたモデルと同程度の読解力を前提にしている。
  - ローカルの小型モデルで得た結果は、Hermes の仕組みの評価には使えない（E012 の同じ条件は luna で 3/3）。
- **限界**: 各1回。Skill なし条件はローカルでは未実施（10回前後の呼び出しが必要で、余白を超える見込み）。
- **次の行動**: ローカルモデルは「動くことの確認」までとし、Skill の評価は実モデルで続ける。
