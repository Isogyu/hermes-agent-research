# E018 自動振り返りが具体的な知識を残す条件を探す（2026-11-21）

- **目的**: O10。E017 で自動振り返りは文書にない慣習を1つも残さなかった。繰り返しやプロンプト調整で残るようになるかを確かめる。
- **仮説**: (a) 同じ業務を同一会話で3か月分繰り返せば、振り返りは「毎回必要な具体値」と認識して残す。(b) 振り返りプロンプトに「文書にない具体値はそのまま残せ」と足せば残す。反証: どちらでも本番で合格しない。
- **方法**: `lab/bench/run_gw_multi.py`。ゲートウェイの Responses API に `conversation` を指定して同一会話にする。(b) は `gateway_patched.py` で起動時にプロンプトへ1段落を追加（Hermes のソースは書き換えない）。モデルは gpt-6-luna、訓練の提出上限は20回。その後、本番（上限3回）を各3回。
- **結果**:

| 条件 | 訓練中の様子 | 振り返り | Skill に残った慣習 | 本番 |
|---|---|---|---|---|
| (a) 3か月繰り返し（m1-repeat3） | 1月: 6回目で受理。2月・3月: どちらも E31 → 受理（2回） | 2回起動 | 0/5（Skill 名 `operational-reporting`） | 0/3 |
| (b) プロンプト追加（m2-patched） | 1月: 6回目で受理 | 1回起動 | 2/5（ヘッダーと作成者行） | 0/3 |

  - (a) の訓練中、会話の履歴に答えがあるのに、2月も3月も同じ E31（分類名の読み替え）で1度拒否された。同じ会話の中でも、学んだことを確実には使えていない。
  - (a) の入力トークンは1月 520k、2月 260k、3月 294k。会話が長くなるほど毎回の送り直しが増える。
  - (b) の Skill には「Known conventions」節ができ、2つの慣習に加えて、**訓練時だけの値**（受付のポート番号 28982、「上限は20回」）も書かれた。本番1回目はその古いポートへ提出し、受付に1度も届かなかった（提出0回）。残り2回は E31・E42・E57 などで3回を使い切った。
- **解釈**:
  - 繰り返しは効かなかった。振り返りは回を重ねるほど一般化を進めた。
  - プロンプトの追加は部分的に効いたが、「残すべき具体値」と「その場限りの値」を区別できなかった。具体値を残す方針は、E012 で見た「古い Skill が黙って誤る」問題を別の形で持ち込む。
  - 自動振り返りが見ているのは会話の記録だけで、どの値が恒常的でどの値が偶然かを判断する材料がない。人が「これを覚えて」と言う明示の経路（E017、3/3）は、その判断を人が補っている。
- **限界**: 各条件の訓練は1回、モデルは luna のみ、追加した文面は1種類。上位モデルなら区別できる可能性はある。
- **次の行動**: この論点はここで一区切りとする。H11（学習は人の指示があって実用になる）は3つの独立した試みで支持された。
