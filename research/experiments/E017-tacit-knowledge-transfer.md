# E017 文書にない知識は Skill で引き継がれるか（2026-11-21）

- **目的**: O9。Skill なしでは失敗する業務で、品質への効果を測る。あわせて「組織の暗黙知の形式知化」に当たる場面を再現する。
- **業務**: E012 の月次レポートに「経理受付サービスへの提出」を足した（`lab/bench/intake_server.py`、`gen_hard_ws.py`）。受付は文書にない慣習を5つ持つ（リクエストヘッダー、作成者行、分類名の読み替え、2行目の通貨表記、末尾のチェックサム）。拒否時は違反を1つだけ教える。**本番は提出3回まで**で、超えると月が締め切られる。したがって初見では合格できない。これは意図した設計で、見たいのは「訓練で得た知識が次に引き継がれるか」。
- **仮説**: 訓練（上限20回）を経た Skill があれば、本番で合格する。反証: Skill があっても同じ拒否を受ける。
- **条件**（gpt-6-luna、各3回、月を変える）:
  - Skill なし
  - 明示: 訓練の依頼文に「学んだことを Skill に保存せよ、来月は初回で受理されるように」と添えた
  - 自動: ゲートウェイで同じ訓練を行い、既定設定の自動振り返りに任せた
- **結果**（詳細は `research/evidence/EV05-tacit-knowledge-results.md`）:

| 条件 | 合格 | 提出回数 | 受付の応答 |
|---|---|---|---|
| Skill なし | 0/3 | 3・3・3 | E11 → E23 → E31（3回とも同じ） |
| 明示的に保存させた Skill | 3/3 | 2・2・1 | E42 → 受理 が2回、初回受理が1回 |
| 自動振り返りの Skill | 0/3 | 3・3・3 | E11 → E23 → E31（Skill なしと同じ） |

  - 訓練はどれも6回目の提出で受理された。
  - 明示の Skill には5つの慣習がすべて書かれた。ただし2行目の通貨表記（E42）の書き方が不正確で、3回中2回は1度拒否されてから直した。
  - 自動振り返りは2回の訓練とも Skill を書いたが、**5つの慣習の記載は0件**。書かれたのは「拒否は新しい慣習の証拠として扱い、指示された修正だけを行え」という一般論。メモリにも書かれなかった。
  - 別モデルでの確認（OpenRouter の nemotron-3-ultra 無料版、各1回）: Skill なしは不合格（3回拒否の後、4回目で締め切り）、luna が書いた明示の Skill ありは2回目で受理。
- **解釈**:
  - 文書にない知識の引き継ぎは、Skill で実現できる。別のモデルが書いた Skill でも通用した。
  - ただし自動の振り返りは、まさに引き継ぐべき具体的な知識を、一般化の過程で落とした。「業務から学ぶ」は、人が「これを覚えて」と言ったときに成り立ち、放置では成り立たなかった。
  - 発表ページの「繰り返し依頼される業務で成功したやり方を自動的に Skill に変換する」は、この実験の範囲では、変換は起きるが中身が役に立たない、という結果。
- **限界・反証**:
  - 業務は、初見では合格できないよう意図的に作ってある。Skill なしの 0/3 は設計の帰結で、発見ではない。発見は残り2条件の差。
  - 自動の訓練は2回、モデルは luna のみ。上位モデルや、同じ業務を何度も繰り返した後の振り返りなら、具体値が残る可能性はある。
  - 振り返りのプロンプトは設定で差し替えられる（エージェント単位の上書きがある）。既定のプロンプトでの結果。
  - 自動の条件はゲートウェイ経由、明示の条件は `-z` で訓練した。経路の違いが混ざっている。
- **次の行動**: (1) 同じ業務を同一セッションで3か月分繰り返してから振り返らせ、具体値が残るかを見る。(2) 振り返りプロンプトに「具体的な値とコマンドを残せ」と足した場合を試す。(3) メモリ（MEMORY.md）への明示保存と Skill を比べる。
