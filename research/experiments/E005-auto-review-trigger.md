# E005 自動の振り返り（Skill 化）はいつ起動するか（2026-11-20）

- **目的**: 「成功したやり方を自動的に Skill に変換する」という主張の起動条件を実行で確かめる。
- **背景・仮説**: EV01 によれば、ツール呼び出し反復が10回に達するとターン終了後に振り返りが起動する。12回のツール呼び出しを行えば、振り返り用のリクエストが偽 LLM に届くはず。
- **方法**: `echo step-N` を12回呼んで終わる台本（`lab/scripts/twelve-steps.json`）。`hermes -z`（r1）と `hermes chat -Q -q … --format stream-json`（r2）で実行し、終了後 25〜40秒待って追加のリクエストを観察。
- **結果**: どちらも届いたのはメインの13リクエストだけ。振り返りは起動しなかった。
- **原因（コードで確認）**: `agent/background_review.py:310-314`。`-z` と `chat -q` は「有限ターン」と判定され、`load_background_review_settings()` が無効を返す。コメントは「振り返りのフォークは約3万トークンで、見ている人がいなくなった後に走らせない」という趣旨。
- **解釈**: 自動の振り返りが働くのは、長く生きるセッション（対話 TUI、メッセージング連携のゲートウェイ）だけ。次の経路では働かない。
  - 1回実行（`-z`、`chat -q`）
  - cron（`cron/scheduler.py:2472`）
  - 委譲された子エージェント
  無人で回す定型業務ほど自動学習の対象外になる。それらの経路で Skill が増えるのは、メインのモデルが自分の判断で `skill_manage` を呼んだときだけ。さらに `-z` では Skill 化を促す文もプロンプトから外される。
- **自分の誤りの記録**: サブエージェントの報告を受けた時点で「10回で起動する」を前提に実験を組んだ。報告には「ワンショットで止まるかは未確認」と書いてあったのに、最初の実験をワンショットで行った。未確認と書かれた点は、実験の前提にする前に先に確かめる。
- **限界**: 長く生きるセッションで実際に起動するところは、まだ観察していない。
- **次の行動**: ゲートウェイの api_server（Foundry 版が使う経路）を立て、同じ台本を流して振り返りのリクエスト・トークン量・書き込み内容を観察する（E006）。
