# E016 自動の振り返りはどんな Skill を書くか（2026-11-21）

- **目的**: O8。自動の振り返りが書く Skill は、効かなかった汎用の手順書か、効いたコードつきか。
- **方法**: `lab/bench/run_gateway_real.sh`。実モデル（gpt-6-luna）のゲートウェイ API に月次レポート業務を1回依頼し、振り返りの完了を待つ。
- **結果**:
  - g5（既定設定）: 業務は7回の呼び出しで完了。しきい値10に届かず、**振り返りは起動しなかった**。E012 の Skill なし条件は7〜11回なので、この規模の業務は既定では起動したりしなかったりする。
  - g6（しきい値を5に変更）: 振り返りが起動。6回の呼び出し、約13万トークン（うちキャッシュ読み 124,672）。業務本体は9回。Skill `productivity/sales-reporting`（1,883バイト、SKILL.md のみ、スクリプトなし）を作成。内容は「現行ルールを読め、スクリプトで計算せよ、書いたものを検証せよ」という汎用の手順（`research/evidence/skills/sales-reporting-auto-review`）。
  - この Skill がある条件（k6-c1auto、3回）: 3/3 合格、呼び出し 10・7・9、入力 151k・102k・135k、33〜42秒。
- **解釈**: 自動の振り返りは、E012 で効果が見えなかった型（汎用の手順書）を書く。E012 のスクリプトつき Skill（呼び出し4回、入力約6万）には遠く及ばない。Skill なし（11回、約19万）よりやや少ないが、ばらつきの範囲。
- **原因の見立て（未検証）**: 振り返りのプロンプトが「CLASS-LEVEL skills」「日付・番号・引用を内容にするな」「規則は出来事なしで成り立つように」と一般化を強く求めている（`agent/background_review.py:488` 付近）。個別業務の具体値やコードは、この方針と相性が悪い。
- **限界**: 訓練1回、モデル1種類、しきい値は既定から変更。
- **次の行動**: 具体的な知識が要る業務で同じことを確かめる（E017）。
