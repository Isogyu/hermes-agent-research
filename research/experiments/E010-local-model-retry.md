# E010 ローカルモデルの再挑戦（2026-11-20）— E002 の結論を訂正

- **目的**: 「ローカル LLM は呼べないのか、どれくらい足りないのか」という問いに実測で答える。
- **背景**: E002 は「8GB では実用にならない」と結論したが、試したのはコンテキスト 24k だけで、失敗時はほかのアプリでスワップが埋まっていた。結論が早すぎた。
- **方法**: `qwen3:4b-instruct` に `num_ctx 12288` の別名 `hermes-lab-qwen3-12k` を作成。依頼は「hello.txt を作り、バイト数を答えよ」。`lab/runs/l1-local12k`, `l2-local12k-declared`。
- **結果**:
  - Ollama 直接呼び出し: 読み込み 12秒、メモリ 3.6GB。動く。
  - Hermes（`ollama_num_ctx` 未指定）: 24秒で拒否。`ollama_runtime_context_too_small`。Hermes は Ollama の実コンテキストを調べ、ツール使用時に 64,000 未満なら実行前に止める（`agent/conversation_loop.py:419-427`）。
  - Hermes（`ollama_num_ctx: 64000` と申告、実体は 12k のまま）: **成功**。211秒、API 呼び出し3回、入力 32,827 トークン、`hello.txt`（6バイト）を作成し正しく回答。
- **解釈**:
  - 足りないのはメモリそのものではなく、Hermes の「64k 以上」という要求。64k を本当に確保すると、このモデルで推定 7GB 前後（4k で 2.9GB、12k で 3.6GB、24k で 4.6GB からの外挿）になり、8GB の機械には載らない。
  - 申告値をごまかせば 12k で動く。ただし固定費が約1万トークンなので、会話に使える余白は 1,500〜2,000 トークンしかない。数回のツール呼び出しであふれる。
  - 1回の呼び出しに約70秒かかる（約1万トークンの読み込み）。
- **限界**: 成功は1回だけ。余白を超えたときの挙動は未確認。4B のモデルが Skill を適切に書けるか・選べるかは別の問題。
- **次の行動**: `-t` でツールセットを絞り、固定費を下げて余白を広げる。余白が 5,000 トークン以上取れれば、小規模な Skill 再利用実験をローカルで回せる。
