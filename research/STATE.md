## 目標
Hermes Agent / Hermes Foundry / Hermes Enterprise が、個人と企業の継続的な業務自動化の基盤としてどこまで使えるかを、実行で確かめる。3つを混同しない。

- **Hermes Agent**: OSS のエージェント本体。`repos/hermes-agent`（commit 2de9f51、v0.23.3+93）。実際に動かして検証中。
- **Hermes Foundry**: Hermes を Microsoft Foundry の hosted agent として動かすための公開パッケージ。`repos/hermes-foundry`（commit 8367c97）。テナントごとに手で入れる POC。ソースとテストで検証。
- **Hermes Enterprise**: 2026-11-18 発表の商用提供。公開コードはなく、発表ページの主張しか確認できない。

## 確認済みの主な発見
1. 実質の Python 要件は 3.14。3.13 では pip が成功を返すのに依存が入らず動かない（E001）。
2. 一言の依頼でも最初のリクエストは約1万トークン。ツール呼び出しのたびにほぼ全量を送り直す（E002、E003）。
3. Skill 一覧は毎リクエストに全件載る。1個あたり約24トークン、2000個で約5.8万トークン。説明は60字で切れ、似た Skill は区別できなくなる（E003）。
4. メインのエージェントが通常ターンで書く Skill は既定で無検査。インジェクションと秘密鍵の送信を含む Skill が保存され、次のセッションの一覧に無害な説明で載った。`skills.guard_agent_created: true` にすれば同じ内容は拒否される（E004）。
5. 自動の振り返りは、1回実行（`-z`、`chat -q`）・cron・子エージェントでは無効。長く生きるゲートウェイでは起動し、権限は絞られ、書き込みは検査される。1回あたり1.4万〜5.7万トークン（E005、E006）。
6. 【2026-11-21 訂正: 別リポジトリ `hermes-collective-wisdom` に実装があった。下記は hermes-agent と hermes-foundry の2つに限れば正しい】発表ページが言う Collective Wisdom（Skill を提案し、レビューを経てチームに公開）に当たる実装は、公開2リポジトリのどちらにもない。Foundry 版の Skill はエージェントのインスタンス単位で、共有されない（EV01、EV02）。
7. Foundry 版は Hermes の端末・ファイル・コード実行・ブラウザを無効にし、M365 用の MCP ツール約40個を主な手段にしている。OSS 版とは使える道具が大きく違う（EV02）。
8. `hermes -z` は裏でゲートウェイの常駐プロセスを起動する（E002）。
9. 危険コマンドの可否は経路で決まる。`-z` は確認なしで実行、`chat -q` は拒否、ゲートウェイは補助 LLM（既定でメインと同じモデル）の1語で決まる（E009）。
10. ゲートウェイ経由の端末コマンドは、既定で利用者のホームディレクトリで実行される。実験では `terminal.cwd` を必ず指定する（E009）。

11. コードつきの Skill は入力トークンを約3分の1、所要時間を約半分にした。何も指定せずに書かせた汎用 Skill には効果が見えなかった（E012）。
12. 業務ルールが変わると、古い Skill は3回中3回、ルール文書を読まずに誤ったレポートを出し、成功と報告した（E012）。
13. 隔離しないと、エージェントは作業フォルダの外を検索して読む。最初の比較はこれで無効になった（E012）。
14. Claude Code / Codex への委任は動くが、Hermes 単独より遅い。下位エージェントが権限で止めた書き込みを、Hermes が代行した（E013）。
15. 自動の振り返りは、既定設定だと7回程度の業務では起動しない。起動しても書くのは汎用の手順書（E016）。
16. 文書にない提出時の慣習5つを要する業務で、明示的に保存させた Skill は 3/3 合格、自動振り返りの Skill は 0/3（Skill なしと同じ拒否）。自動振り返りは2回の訓練とも慣習を1つも残さなかった（E017）。
17. OpenRouter の無料モデル（nemotron-3-ultra）は Hermes で動く。Gemini は 3.8-flash が無応答、3.6-flash は遅い。Gemini のキーが無料枠かは未確認（E015）。
18. 同じ業務を同一会話で3か月繰り返しても、自動振り返りが残した慣習は0/5。プロンプトに「具体値を残せ」と足すと2/5になったが、訓練時だけのポート番号も書き込み、本番では 0/3（E018）。
19. 公開情報には Skill 学習の効果を独立に測った評価が見当たらない（EV06、検索2件のみ）。

## 問いの立て直し（2026-11-21）
利用者の指摘「検証して何に繋がるのか」を受け、機能を順に試す計画は破棄した。問いは次の2つ。
- **問い1**: Hermes が Claude Code / Codex を超える分野や作業はあるか。
- **問い2**: 仕事のあり方を変えられるか（常駐して業務を引き受け、使うほど任せられる範囲が広がるか）。記事にするかは結果を見て利用者が判断する。

DeepResearch の結果は EV07（Hermes）と EV08（仕事を変える道具全般）。挙げられたリポジトリ2件、Issue 9件、論文4件は実在を確認した。Cloudvisor の5か月運用記（LinkedIn）は URL がなく未確認。

公開情報で決着したこと（実験し直さない）:
- 常駐、cron、チャット連携、記憶、Skill、子エージェントは Claude Code（Skills、Cloud Routines、Claude Tag）と Codex（Skills、Memories、Automations）にもあり、機能の有無では差がない。
- 人が整えた Skill は効き、モデルが自作した Skill は平均で効かない（SkillsBench、arXiv 2602.12670）。外部の評価なしに Skill を書き直し続けると一般論に寄って専門知識が失われる（arXiv 2611.25534）。E016〜E018 と同じ向き。
- Skill が増えると選択精度が落ちる（arXiv 2608.14036、Issue #76307、#89844）。
- hermes-agent-self-evolution は未成熟で、書き戻しが動かないという Issue がある。調べない。
- 残る構造上の差は、自前運用、モデルを選ばないこと、複数のチャット基盤の3つ。

## 研究の終了（2026-11-21）
仮説 N1〜N3（Claude Code / Codex との直接比較、10日分の圧縮運用）は**実施しない**。理由: 結果の予想が「道具より運用」で、EV08 の独立研究がすでに導いている結論をなぞるだけになる。合成の業務では「利用者の仕事が変わるか」は測れない。利用者と合意のうえ、ここで研究を閉じる。

### 結論
- **問い1（Claude Code / Codex を超える分野はあるか）**: 見つからなかった。機能の有無では差がなく、コーディングで上回る根拠もない。残る差は、自前運用、モデルを選ばないこと、複数のチャット基盤の3つで、これが要る人にだけ価値がある。
- **問い2（仕事のあり方を変えられるか）**: 合成の実験では答えが出ない。実測と公開研究が一致して示すのは、「自動で学ぶ」は働かず、「人が手順を明示して保存する」は働く、ということ。
- **公開情報にない実測として残るもの**: 自動の振り返りが具体的な知識を落とすこと（E016〜E018）、無人経路で自動学習が無効なこと（E005）、古いスクリプトつき Skill が黙って誤り成功と報告すること（E012）、Skill 2000個で一覧が約5.8万トークンになること（E003）、下位エージェントの権限拒否を上位が代行したこと（E013）。
- **限界**: 各条件3回、主なモデルは gpt-6-luna の1種、業務は架空の2種類。Enterprise と Collective Wisdom は手元で試せていない。

## 研究方法の振り返り
- うまくいった点: 偽 LLM にしたことで、送信内容を全部記録でき、1実行 5〜10秒で回せた。見積もりトークンは実トークナイザと約4%の差で一致した。
- 失敗した点: サブエージェントが「未確認」と書いた点（ワンショットで振り返りが止まるか）を前提にして E005 を組んだ。結果的に重要な発見になったが、設計としては確認が先。
- 失敗した点: 作業フォルダ名の空白が Foundry のテスト2件を壊した。外部リポジトリのテストは空白のないパスで走らせる。
- 失敗した点: 最初の Skill 比較で作業フォルダを隔離しておらず、対照条件が汚染された。ツール呼び出しの監査で気づいた。比較実験では、エージェントが読める範囲を先に確かめる。
- うまくいった点: 「効果があった」で止めず、ルール改定の反証実験まで行ったことで、速さと脆さが同じ原因から来ると分かった。
- グラフは現時点では記録の整理にとどまる。仮説が増えて矛盾の検出が必要になったら活用する。
