# Hermes Agent 実証研究

Nous Research の Hermes Agent を 1 台の PC で実際に動かし、「使うほど賢くなる」という主張がどこまで成り立つかを確かめた記録です。期間は 2026 年 11 月 20 日から 21 日、実験は 18 件です。

結論を先に書くと、**人が「これを覚えて」と指示して保存させた手順は効き、エージェントが自動で書いた手順は効きませんでした。**

## 対象

| 名前 | 何か | この研究での扱い |
|---|---|---|
| Hermes Agent | OSS のエージェント本体（v0.23.3 系、commit 2de9f51） | 実際に動かして検証 |
| Hermes Foundry | Microsoft Foundry 上で動かすための公開パッケージ（commit 8367c97） | ソースを読み、テストを実行 |
| Hermes Enterprise | 商用の提供形態 | 公開情報の確認のみ |

Nous Research の言語モデル「Hermes」シリーズは対象外です。

## 主な結果

### 1. 自動の学習は、引き継ぐべき知識を落とす

文書に書かれていない慣習を 5 つ知らないと受理されない、架空の提出業務を作りました。提出は 3 回までです。

| 条件 | 合格 | Skill に残った慣習 |
|---|---|---|
| Skill なし | 0/3 | — |
| 人が保存を指示して書かせた Skill | 3/3 | 5/5 |
| 自動の振り返りが書いた Skill | 0/3 | 0/5 |
| 同じ会話で 3 か月分繰り返してから振り返り | 0/3 | 0/5 |
| 振り返りに「具体値を残せ」と追記 | 0/3 | 2/5 |

自動の振り返りは、具体的な値を省いた一般的な手順書を書きました。「具体値を残せ」と追記すると、訓練時だけのポート番号まで書き込み、本番で古い宛先に提出しました。恒常的な値と偶然の値を区別できていません。

### 2. 速さと脆さは同じ原因から来る

月次の売上レポートを作る架空の業務での結果です。値は 3 回の平均です。

| 条件 | 合格 | API 呼び出し | 入力トークン | 秒 |
|---|---|---|---|---|
| Skill なし | 3/3 | 11 | 187,862 | 44 |
| 文章だけの Skill | 2/3 | 10 | 156,289 | 58 |
| スクリプトつきの Skill | 3/3 | 4 | 59,467 | 24 |
| ルール改定後、Skill なし | 3/3 | 8 | 151,869 | 41 |
| ルール改定後、古いスクリプトつきの Skill | 0/3 | 5 | 74,173 | 25 |

スクリプトつきの Skill は入力を約 3 分の 1 にしました。しかし業務ルールが変わると、3 回とも改定後の文書を読まずに誤ったレポートを出し、成功と報告しました。

### 3. 自動の学習は、無人の経路では動かない

自動の振り返りは、1 回実行（`-z`、`chat -q`）、cron、子エージェントでは起動しません。常駐のゲートウェイでは起動します。定期実行で使うほど学ぶ、という使い方は成り立ちません。

### 4. そのほか

- 一言の依頼でも、最初のリクエストは約 1 万トークンあります。
- Skill の一覧は毎回すべて送られ、2000 個で約 5.8 万トークンになります。説明は 60 字で切られます。
- 通常のターンでエージェントが書く Skill は、既定設定では安全検査を通りません。悪意のある指示を含む Skill が保存されました。`skills.guard_agent_created: true` にすると拒否されます。
- 危険なコマンドの可否は、起動の経路で変わります。`-z` は確認なしで実行します。
- Claude Code や Codex への委任は動きますが遅くなります。同じ課題で、Hermes 単独は 34 秒、Codex への委任は 61 秒、Claude Code への委任は 307 秒でした。
- Python は実質 3.14 が必要です。3.13 では導入が成功したように見えて動きません。

## 公開研究との関係

2026 年の独立研究は、同じ向きの結果を出しています。

- 人が整えた Skill は効き、モデルが自作した Skill は平均で効かない（[SkillsBench](https://arxiv.org/abs/2602.12670)）。
- 外部の評価なしに Skill を書き直し続けると、一般論に寄って専門知識が失われる（[arXiv 2611.25534](https://arxiv.org/abs/2611.25534)）。
- Skill が増えると、正しく選ばれる割合が落ちる（[arXiv 2608.14036](https://arxiv.org/abs/2608.14036)）。

Hermes の自動の振り返りそのものを、同じ業務で繰り返し測った公開の評価は、調べた範囲では見つかりませんでした。

## 限界

- 各条件の実行は 3 回です。傾向は言えますが、数字としては弱いです。
- 主に使ったモデルは 1 種類（`gpt-6-luna`）です。上位のモデルでは結果が変わる可能性があります。
- 業務は架空の 2 種類です。
- Hermes Enterprise と Collective Wisdom は、チーム契約が必要なため試していません。
- Claude Code や Codex と同じ業務で比べたのは 1 件だけです。
- Hermes Agent は更新が速く、ここでの結果は 2026 年 11 月の版のものです。

## 再現の手順

1. Hermes Agent を `repos/hermes-agent` に取得し、commit 2de9f51 に合わせます。
2. uv で Python 3.14 の環境を作ります。

   ```bash
   cd repos/hermes-agent
   uv sync --frozen --python 3.14 --extra mcp --extra acp --extra anthropic --extra messaging
   ```

3. `env.sh` とスクリプト内の `LAB` を、自分の環境のパスに書き換えます。
4. 仕組みの検証は、API キーなしで動きます。

   ```bash
   source env.sh
   lab/mock/run.sh smoke lab/homes/smoke - "hello"
   ```

5. 実モデルでの実験は `lab/bench/run_real.sh` と `lab/bench/run_hard.sh` を使います。モデルの設定は各自で用意してください。

実験用の設定はすべて `HERMES_HOME` で隔離しています。既存の `~/.hermes` には触れません。ゲートウェイ経由で端末を使う実験では、設定に `terminal.cwd` を必ず入れてください。入れないと、ホームディレクトリでコマンドが実行されます。
